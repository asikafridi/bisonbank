Nerd Notes — Compiler Design Deep Dive

File: atm.l

Flex is a lexical analyzer generator. It takes a set of regular expressions and produces C code that scans input and returns tokens.

  • Rules: Each rule is a pattern (regex) followed by an action. For example, "CREATE" matches the literal string and returns the token CREATE.
  • yylval: A global variable used to pass semantic values (e.g., the number value for NUMBER) to the parser.
  • yylineno: Tracks the current line number for error reporting.
  • Whitespace: Ignored via [ \t]+ to keep the token stream clean.
  • Newline: Returned as NEWLINE so the parser knows when a command ends.

Token Flow Example: The input CREATE ACCOUNT John 1234 Dhaka secret becomes the token stream: CREATE, ACCOUNT, NAME("John"), NUMBER(1234), NAME("Dhaka"), NAME("secret"), NEWLINE.

Expert Insight

Flex uses DFA (Deterministic Finite Automaton) to efficiently match patterns. The %option yylineno adds line counting, which is crucial for debugging. The lexer is the first stage of the compiler pipeline, converting raw text into a structured token stream.

File: atm.y

Bison is a parser generator that builds an LR(1) parser from a context‑free grammar. It defines the syntactic structure of the language and executes C code actions when rules are matched.

  • Grammar Rules: Each rule has a left‑hand side (non‑terminal) and a right‑hand side (terminals and non‑terminals). For example, statement: create_account | login | ...
  • Semantic Actions: C code enclosed in { ... } that runs when the rule is reduced. Actions access rule components using $1, $2, etc., and set the result via $$.
  • %union: Defines the possible types for tokens and non‑terminals (e.g., int num for NUMBER, char* str for NAME).
  • Session State: Global variables (e.g., state, current_ac_index) are updated within actions to maintain login status and transaction context.

Parsing Example: The token stream from the lexer is fed into Bison. When it matches the rule create_account: CREATE ACCOUNT name NUMBER name name, the action creates a new account in the accounts array, assigns a number, and prints a success message.

Expert Insight

Bison’s LR(1) parsing is powerful enough to handle complex grammars. The %type directives ensure type safety between tokens and non‑terminals. This is a classic implementation of a command‑line interpreter using compiler construction techniques.

Files: server.js · script.js · index.html

The Node.js server spawns the compiled ATM binary as a child process, piping stdin/stdout. Each command sent via the web UI is written to the process, and the output is captured and returned to the frontend.

Server (Node + Express)

Uses spawn() to launch the ATM. A buffer collects stdout/stderr and a setTimeout flushes after 500ms of silence — this ensures complete command output. REST endpoint /command accepts POST requests.

Frontend (HTML + CSS + JS)

Vanilla JS with fetch() to talk to the server. Keypad buttons are dynamically generated based on user/admin mode. The display updates in real‑time with a monospace terminal look.

User → (Web UI) → Node.js Server → (stdin) → ATM Binary (Flex + Bison) → (stdout) → Server → (JSON) → UI

The ATM binary is compiled from atm.l and atm.y using Flex and Bison. It maintains in‑memory account data, session state, and transaction history. The web server acts as a bridge, making the command‑line tool accessible via a beautiful interface.
